## 1. 产品概述

### 1.1 产品定位

StudyLog 是一个**单人使用、以成绩数据为核心的轻量学习轨迹追踪工具**。它不承担教学功能，而是解决一个问题：

> 初三这一年是冲刺中招的关键期，考试频率高（周测、月考、期中期末、模拟考），成绩散落在纸质试卷、班级群通知、家长手机截图里。**家长和学生能记住"最近考了多少分"，但很难回答"哪一科在持续下滑""这次比上次退步了多少""和长期水平比是好了还是差了""离目标高中还差多少分"。**

StudyLog 把这些散落的成绩结构化沉淀下来，并用图表与智能分析把"趋势""薄弱点""与目标院校的差距"显性化，服务 2027 年 6 月中招前的长期备考决策。

### 1.2 目标用户与角色

本系统为**单用户自用**定位，**无登录、无鉴权**，打开应用即直接进入首页。不存在多账号、多租户或只读访客概念。

| 角色 | 说明 | 主要操作 |
| --- | --- | --- |
| 主用户（家长 / 学生） | 唯一使用者 | 录入、查看、配置、导出、AI 分析、目标院校对比 |

> 说明：v1.0 中的"访问口令登录"与"只读分享"已按用户意见**移除**。若需限制公网访问，属于部署层能力（如反向代理白名单、内网/隧道访问），不在应用内实现。

### 1.3 核心使用场景

| 编号 | 场景 | 触发频率 | 相关功能 |
| --- | --- | --- | --- |
| S1 | 周测后，家长把班级群里各科分数逐科手动填入 | 每周 1–2 次 | 手动录入 |
| S2 | 月考成绩单是老师发的长文本/截图，复制整段让 AI 自动拆解成各科成绩 | 每月 1 次 | 智能批量录入 |
| S3 | 期中/月考后，想看看"总分有没有进步、哪科退了" | 阶段性 | 总分/单科趋势、进退对比、均值对比 |
| S4 | 想掌握自己在班里、年级的位置变化 | 每次考试后 | 排名录入、排名趋势与名次进退 |
| S5 | 需要一份"薄弱点在哪、下一步怎么补"的结论 | 阶段性 | 智能学情分析 |
| S6 | 想知道"离郑州外国语学校 / 郑州一中 / 河南省实验中学还差多少分" | 阶段性 | 目标院校对比 |
| S7 | 中招前回看初三整年的全部考试记录 | 阶段性 | 历次考试全量总览、导出 |

### 1.4 产品边界（本期范围界定）

**做：**
- 全中招科目范围的成绩记录（含等级呈现科目）
- 手动单科/整场录入 + 大模型辅助的批量文本录入
- 成绩可视化（总分趋势、单科趋势、进退对比、均值对比、全量总览、排名趋势）
- 班级排名 / 年级排名（总分 + 可选单科）
- 目标院校录取线对比（差距与提分空间）
- 大模型驱动的薄弱点分析（含无 AI 时的规则兜底）
- 数据导出/备份、科目与分值可配置

**不做（本期）：**
- **登录、鉴权、只读分享、多账号体系**
- 多学生对比、班级大盘（仅记录本学生排名，不采集他人数据）
- 题库、错题本、作业管理、学习计划打卡
- 社交、内容社区、付费与运营体系
- 移动端原生 App（仅做 Web 自适应）

> 边界理由：本期是**单人自用的数据工具**，功能收敛能显著降低低配服务器（2 核 2GB）的资源压力与开发复杂度。

## 2. 业务背景与科目口径

### 2.1 政策事实（已核实）

以下为设计科目的依据，来源于郑州市教育局 / 河南省教育厅公开政策：

- 郑州市区**中招录取总成绩为 730 分**（适用于 2027 年中招，与近三年口径一致）。
- 全省统一命题考试科目为**语文、数学、英语、道德与法治、历史、物理、化学**（合计 600 分）。
- **体育考试按 100 分计入**中招录取总成绩；**理化生实验操作考试按满分 30 分计入**。
- 河南省教育厅已明确：**自 2027 年起，实验操作考试科目由物理、化学、生物学调整为物理、化学**，对象为**九年级学生**，**全省统一命题**，仍在初三下学期（约 4 月）进行，**仍以 30 分计入总分**。
- **生物学实验操作改为考核**，在**初二下学期期末**进行，成绩以等级呈现，不计入总分。
- **初中生物学、地理**实行"学完即考"，考试对象为**初二年级学生**，成绩以**等级（A/B/C/D）**呈现，不计入总分。

> **用户现状（按修订意见）**：用户现已是**初三（九年级）学生**，将参加 **2027 年 6 月中招**。因此化学、物理/化学实验操作**均已在学**；生物、地理等级考试**已在初二下学期完成**，属**历史/已完成项**，仅作留档展示，不再参与日常录入与总分。

### 2.2 科目与分值口径表（系统默认配置）

> **v1.2 关键变化：科目字典按「学段」分别维护。** 初二与初三的**考试科目集合**与**科目满分**并不相同，因此系统不再只有一套满分口径，而是按学段维护两套字典，各学段的总分满分由该学段字典推导（初二 570 / 初三 730）。

**初二（八年级）口径 —— 计入总分满分 570**

| 科目 | 满分 | 计分方式 | 计入总分 |
| --- | --- | --- | --- |
| 语文 | 120 | 分数 | 是 |
| 数学 | 120 | 分数 | 是 |
| 英语 | 120（含听力） | 分数 | 是 |
| 物理 | 70 | 分数 | 是 |
| 道德与法治 | 70 | 分数 | 是 |
| 历史 | **70** | 分数 | 是 |
| 生物 | 100 | 等级（A/B/C/D） | 否 |
| 地理 | 100 | 等级（A/B/C/D） | 否 |

核算：120 + 120 + 120 + 70 + 70 + 70 = **570 分**；初二尚未开设化学、体育与理化生实验操作。

**初三（九年级）口径 —— 计入总分满分 730（中考口径）**

| 科目 | 满分 | 计分方式 | 计入总分 |
| --- | --- | --- | --- |
| 语文 | 120 | 分数 | 是 |
| 数学 | 120 | 分数 | 是 |
| 英语 | 120（含听力） | 分数 | 是 |
| 物理 | 70 | 分数 | 是 |
| 化学 | 50 | 分数 | 是 |
| 道德与法治 | 70 | 分数 | 是 |
| 历史 | **50** | 分数 | 是 |
| 体育 | 100 | 分数 | 是 |
| 理化生实验操作 | 30 | 分数 | 是 |

核算：120 + 120 + 120 + 70 + 70 + 50 + 50 = 600（全省统考 7 科）+ 体育 100 + 实验操作 30 = **730 分**，与政策一致。

**两学段差异清单（必须在界面上显式区分，不可混算）**

| 对比项 | 初二 | 初三 |
| --- | --- | --- |
| 计入总分满分 | 570 | 730 |
| 化学 | 未开设 | 50 分计入总分 |
| 历史 | 70 | 50 |
| 体育 / 理化生实验操作 | 未开设 | 100 / 30 |
| 生物 / 地理 | 等级制、不计总分 | 未开设（字典中不启用） |

**关键设计结论：**

1. **科目必须可配置，不能硬编码。** 政策存在调整（如 2027 起实验操作科目变化），因此科目表、满分、是否计入总分、是否等级呈现均为可编辑配置；**"科目满分 / 是否计入总分 / 是否启用" 按 (科目, 学段) 维度维护**，同一科目（如历史）在两学段可有不同满分。
2. **满分取所在学段的字典值，**不存"每次考试满分快照"。同时区分两个概念：**本次已录科目卷面满分**（如初三 10 月月考实际只考 7 科 = 600）与**学段计入总分满分**（初三 730 中考口径）。趋势图参考线取前者，目标院校对比取后者。
3. **全面移除"得分率"指标。** 趋势、进退对比、均值对比、全量总览、导出与 AI 摘要一律使用**原始分（本学段口径）**，不再计算得分率。
4. **等级科目不进入总分与分数折线。** 生物、地理单独以等级序列展示，且不计入总分。
5. **跨学段数据不放同一张总分图。** 因总分满分不同（570 vs 730），总分趋势按学段分开查看；单科趋势提供"跨学段可比"，**仅混连两学段满分相同的科目**（语文/数学/英语/物理/道法），历史等满分不同的科目不参与跨学段混连。
6. **目标院校录取线为中考（初三 730）口径**，因此该对比功能**仅对初三学段开放**；初二学段下首页与目标页给出"切到初三后再查看"的提示。

### 2.3 考试类型口径

| 类型 code | 名称 | 典型频率 | 是否计入趋势 |
| --- | --- | --- | --- |
| `unit` | 单元测 | 不定期 | 是（可开关） |
| `week` | 周测 | 每周 | 是（可开关，默认开启） |
| `month` | 月考 | 每月 | 是 |
| `midterm` | 期中考试 | 每学期 1 次 | 是 |
| `final` | 期末考试 | 每学期 1 次 | 是 |
| `mock` | 模拟考（中招模拟） | 初三阶段 | 是 |
| `sport` | 体育测试 | 初三阶段（体考前后） | 是 |
| `lab` | 实验操作测试 | 初三阶段（2027 年 4 月前后） | 是 |
| `other` | 其他 | — | 是 |

> 设计要点：不同考试类型的**权重与代表性差异很大**（周测波动大，期中期末与模拟考更权威）。因此趋势图必须支持按考试类型筛选，且"历史均值"默认使用**近 8 次同类或全部已选考试**的滑窗，而非全部历史，避免早期低分长期拉偏基准。体育测试与实验操作测试通常只考单一科目，单列类型便于归类与筛选。

### 4.2 模块依赖关系

```
        M1 系统与配置（地基：科目字典/统计参数）
                 │
                 ├──────────────► M2 考试管理（含排名）
                 │                      │
                 │                      ├──────► M3 手动录入 ──┐
                 │                      │                     │
                 └──────────────────────┴──────► M4 智能批量录入 ──┤
                                                                  │
                                            M5 可视化分析 ◄───────┘（依赖已入库的结构化成绩与排名）
                                                  │
                                                  ├──────► M6 智能学情分析
                                                  └──────► M7 目标院校对比
```

**关键依赖结论：**

- **M1 必须先于一切**：科目字典决定了所有录入、统计、图表的口径。M1 未定型前，M2–M7 无法稳定开发。
- **M5 只读、纯计算**：不产生新数据，仅对已有成绩做聚合与渲染，可与其他模块并行开发，但联调需 M2/M3 有可用数据。
- **M6 依赖 M5 的统计口径**：智能分析的输入应是 M5 已算好的结构化摘要（而非原始成绩表），确保"图表展示的结论"与"AI 说的结论"口径一致。
- **M7 依赖 M5 的总分口径**：目标对比以"中考口径总分"为基准，复用 M5 的统计口径，避免两处重复计算。
- **M4 是 M3 的增强路径**：M4 的最终入库复用 M2 + M3 的写入逻辑，因此 M4 必须排在 M2/M3 之后。

### 5.4 关键流程说明

**流程 1：手动录入一次周测**

```
进入 /entry → 选"手动录入" → 填考试信息（名称/日期/类型/年级/学期）
  → 填总分班级/年级排名与人数 → 录入各科得分（满分固定） → 实时校验
  → 保存（事务：写 exam（含排名）+ 批量写 exam_score）
  → 跳转 P5 考试详情，展示"较上次对比"与名次进退
```

**流程 2：粘贴文本批量录入**

```
进入 /entry/ai → 粘贴成绩单文本 → 可选填考试信息
  → 调用解析接口 → 展示"识别 N 项 + 告警 M 项"（含排名若能识别）
  → 用户逐项校对（可改科目、改分、删行、加行、改排名，未识别项需处理）
  → 确认入库（事务：create exam + upsert scores + 排名）
  → 跳转 P5，提示入库结果
  → 失败（超时/额度/格式）→ 展示原因 → 一键转手动录入
```

**流程 3：查看趋势并生成分析**

```
进入 /trend → 选类型/时间范围/合计科目 → 总分折线、单科折线、排名趋势更新
  → 查看"连续下滑预警"
  → 点"生成学情分析"（带当前范围）→ P7 生成报告（含排名趋势与目标差距）
  → 报告持久化，可在"历史报告"中回看
```

**流程 4：查看与目标院校的差距**

```
进入 /targets → 自动计算"中考口径总分"（各科最近一次得分之和）
  → 展示与三校近三年录取线的差距与提分空间
  → 查看"我的总分 vs 录取线"走势对比
  → 可切换基准考试/均值口径；结合薄弱科目给出提分优先项
```

### 6.2 核心实体说明

| 实体 | 业务含义 | 关键规则 |
| --- | --- | --- |
| `subject` 科目 | 中招科目**身份**字典（科目名、标识、计分方式） | 一旦被成绩引用则只可停用不可删除；`score_mode='grade'` 的科目不参与总分计算 |
| `subject_grade` 学段科目 | **按 (科目, 学段) 维护满分、是否计入总分、是否启用、排序** | 同一科目在初二/初三可有不同满分（历史 70/50）；该学段合计满分即其"计入总分满分"（初二 570 / 初三 730） |
| `exam` 考试 | 一次考试的元信息（名称、类型、日期、**学段**、学期、状态、总分排名与人数） | `status='draft'` 的考试默认不计入趋势统计；排名为可空用户录入值；**总分与各科满分口径由 `grade` 决定** |
| `exam_score` 考试成绩 | 某次考试某科目的得分/等级事实记录 | `(exam_id, subject_id)` 唯一；**不再存储每次满分快照**；单科排名可选 |
| `exam_type_dict` 考试类型 | 考试类型字典 | 支持启用/停用，停用不影响历史记录展示 |
| `ai_parse_task` 解析任务 | 一次批量解析的原始文本与结构化结果 | 用于校对回溯与效果复盘；`status` 标识 draft/parsed/confirmed/failed |
| `analysis_report` 学情报告 | 一次智能分析的结论留档 | 记录分析范围、模型与生成时间；结论以 Markdown 正文 + 结构化分区字段双存 |
| `app_config` 系统配置 | 单用户系统的键值配置 | 存统计分析参数、科目别名表等；**不含口令与 AI 密钥** |
| `audit_log` 审计日志 | 记录写操作（建/删考试、改成绩、导入恢复） | 仅追加不改写；用于误删误改后的回溯定位（对应风险 R-9） |
| `target_school` 目标院校 | 目标高中及其属性 | 默认内置三所目标院校；可增删改 |
| `school_admission_score` 录取线 | 目标院校某年度某口径的录取分数线 | `(school_id, year, admission_type)` 唯一；带**当年总分口径满分**，跨口径比较前先折算 |
| `schema_version` 迁移版本 | 数据库结构版本记录 | 不支持业务功能，由迁移执行器维护，保证结构演进可追溯 |

> 物理实现补充：`subject`、`subject_grade`、`exam`、`exam_score`、`exam_type_dict`、`app_config`、`ai_parse_task`、`analysis_report`、`audit_log`、`target_school`、`school_admission_score` 共 11 张业务表，外加 `schema_version` 与只读视图 `v_exam_summary`（考试汇总，按考试学段 LEFT JOIN `subject_grade` 取满分）。表名与字段名以《02-开发手册.md》第 4.3 节 DDL 为唯一基线。

### 6.3 业务字段与取值约束

**`subject`（科目身份）**

| 业务字段 | 取值约束 | 说明 |
| --- | --- | --- |
| `code` | 唯一，小写下划线 | 如 `chinese`、`math`、`english`、`physics`、`chemistry`、`politics`、`history`、`biology`、`geography`、`pe`、`lab_op` |

### 6.4 派生指标口径（业务定义，前后端必须统一）

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| 总分 | `Σ(计入总分科目且未缺考的 score)` | 总分趋势、进退对比 |
| 中考口径总分 | `Σ(每个计入总分科目取"最近一次已录入得分")` | 目标院校对比（满分 730） |
| Δ得分 | `本次科目得分 − 上次科目得分` | 单次进退对比（单科） |
| Δ总分 | `本次总分 − 上次总分` | 单次进退对比（总分） |
| 历史均值 | 所选窗口（默认近 8 次已确认考试）内该科原始分的算术平均 | 均值对比基准 |
| 差值 | `本次科目得分 − 历史均值` | 高于/低于均值判定 |
| 连续下滑 | 连续 N（默认 3）次该科原始分严格递减 | 预警 |
| 名次进退 | `上次名次 − 本次名次`（正=进步，负=退步） | 排名对比 |
| 与录取线差距 | `录取线 − 中考口径总分`（负=需提分，正=已超线） | 目标院校对比 |
| 提分空间 | 同"与录取线差距"，表述为达到录取线所需提升的分数 | 目标院校对比 |
| 等级等效值 | `A=4 / B=3 / C=2 / D=1` | 等级科目可选折线展示，默认关闭 |

> **重要口径约定**：
> 1. **满分按学段**：各科满分取**该学段**科目字典的满分值（`subject_grade`），学段计入总分满分由字典推导（初二 570 / 初三 730），不再存"每次考试满分快照"、不再计算得分率。用户录入前须将校内卷面分**按本学段口径折算**。同一场考试的"总分"为本次实际录入且计入总分科目得分之和，与"学段计入总分满分"是两个概念，页面须同时标注。
> 2. **总分口径提示**：单次考试的"总分"为本次实际录入且计入总分科目得分之和；当某次考试未覆盖全部科目时，页面须标注覆盖科目与本次已录科目卷面满分，并提供"合计科目"筛选以对齐口径，避免误读。
> 3. **排名方向提示**：排名数值越小越好，排名趋势图 Y 轴必须反向；名次变化文案用"进步/退步 N 名"，不用上升/下降箭头单独表达，避免与分数趋势混淆。
> 4. **跨学段不可混算**：初二的 554/570 与初三的 573/730 不可直接比较；总分趋势按学段分开查看，单科趋势仅混连两学段满分相同的科目。

## 7. 验收标准

| 模块 | 验收要点 |
| --- | --- |
| M1 系统与配置 | 打开应用直达首页、无任何登录拦截；默认科目与分值按**学段**预置正确（初二 570 / 初三 730）；科目可按学段增删改且引用校验生效；导出入备份可往返一致；AI 状态仅只读展示 |
| M2 考试管理 | 考试增删改查正常（含**学段**字段）；删除级联清理成绩；列表按学段筛选与分页正确；草稿不计入趋势；总分班级/年级排名可录入且人数校验生效 |
| M3 手动录入 | 切换学段按该学段科目字典重建表格（初二无化学/体育/实验，历史满分 70）；得分 > **该学段**该科满分被拦截；等级科目按 A/B/C/D 录入；缺考不计入总分；移动端可正常录入 |
| M4 智能批量录入 | 典型老师口吻成绩单文本可正确拆分为科目+分数（含排名时一并提取）；**解析前先选学段**并按该学段满分提示模型；未识别/疑似科目有告警；**必须经过校对步骤**；入库为原子操作；AI 失败可降级到手动 |
| M5 可视化分析 | 总分与单科折线（原始分）正确；**总分趋势按学段分开、单科趋势"跨学段可比"仅含满分一致的科目**；切换筛选不整页重渲染（不回弹顶部）；排名趋势 Y 轴反向且名次进退文案正确；进退与均值对比数值与手算一致；全量总览矩阵含排名列且按学段分列；360px 宽度下可用 |
| M6 智能分析 | 报告数字与 M5 统计（含排名、目标差距）一致，无编造数据；报告正文为纯中文、无英文技术名词；未配置 AI 时规则报告可用；报告可留档回看 |
| M7 目标院校对比 | 内置三校近三年录取线正确；中考口径总分与差距/提分空间计算正确；走势对比图正确；院校与分数线可维护；**初二学段不展示对比结果而给出提示** |
| 非功能 | 常驻内存 < 250MB；gzip 后首屏资源 < 300KB；健康检查可用；自动备份按日生成 |
